## 1. 优先级与资源说明

优先级（冲突时从高到低）：
1. 本文档明确的功能、文案真实性、安全约束，以及**最新修订**。
2. `references/final/01-homepage.png` 至 `05-about-us.png` 的结构、配色、排版气质。
3. `references/brand/logo-original-reference.jpg`：用户提供的原始视觉参考，应尽可能忠实使用其品牌标识与中文、藏文字样。请注意这是**整张品牌宣传图，不是透明抠图 Logo**。不要把整张图强行缩到导航栏；需要谨慎裁切或制作独立的可复用品牌资产，保留原图备查；无法准确提取藏文时先以图片裁切或等待确认，不要凭空编写藏文。
4. `references/notes` 为解释修改要求的历史参考，**不应覆盖最终版**。

**最终修订重点**：
- 首页使用最初选择的「方案 A 藏式典雅」的雪山、藏地建筑、织纹氛围，主体色系 **高原蓝 + 暖米白 + 克制金色/少量藏红**，文化温度高于商业营销感。
- 首页**必须有独立商务果切展示板块**，只展示下述五种场景，不在首页选择规格。
- 果礼选择逻辑：**选择系列 → 查看本系列商品 → 查看商品详情 → 微信/电话咨询**。
- 果切选择逻辑：**选择场景 → 选择该场景套餐 → 选择规格 → 微信/电话咨询**。场景先于规格，不能重复出现规格选择器；不存在“其他场景推荐”区域。
- 任何页面**不得出现填写定制需求、提交预订信息、收集手机号等表单**，也不使用诱导弹窗、虚假评价、虚构客户案例/价格/资质。
- 同一个页面不要重复堆砌相同功能块、同样的图片网格、多个重复咨询区。
- 首页底部**将旧版抽象山峦页脚主题替换成苹果与高原果园主题摄影表现**：可以做页脚上方的横幅背景；不要卡通苹果、满屏红色；联系信息保持可读。`references/notes/footer-to-revise.png` 是需要修改的旧页脚截图，**不是要照搬的目标**。若缺少真实苹果果园照片，请用专门的 `apple-orchard` 替换占位模块，而不是自称已有真实素材。
- 缺少商品照、返图、微信二维码、真实门店照片、营业时间及地址时保留**明确的占位**，不要生成假的二维码，也不要捏造事实。

## 2. 技术方案

优先 Next.js App Router + React + TypeScript + Tailwind CSS。若仓库已有合适技术栈，沿用已有工程，避免破坏性改造。可以使用开源图标库。建议静态内容使用独立 TS/JSON 配置，初期不需要数据库、CMS、后台管理、账户、购物车或支付。务必保留未来替换素材、增删产品/套餐/案例的便利性。

目录建议：`app/`、`components/`、`content/`、`public/images/`、`styles/`，可按现有项目结构调整。

页面路径：`/`、`/gifts`、`/fruit-cuts`、`/cases`、`/about`，另可用 `/gifts/[slug]`、`/fruit-cuts/[slug]`、`/cases/[slug]`，或者可访问的详情弹层。不应增加仅为装饰的空页。

品牌资料已确认：
- 品牌中文名「藏果源」；原始品牌图片见 `references/brand`。
- 业务：鲜果、果礼、果切、果汁（果汁目前非核心栏目，不要无根据扩展产品）。
- 联系电话：**176 1116 8853**；实现 `tel:17611168853`。
- 商业地址、营业时间、微信/小程序链接、价格、服务范围：**未确认，必须占位或省略**。

## 3. 统一视觉系统

- 高原蓝：用于首屏、选中状态或特色区块。暖米白纸张质感：主背景。藏红仅在选中、强调、少量纹样出现。金色为分割线/细节，不能显得金碧辉煌。
- 采用大留白、编辑式版面、果品摄影。藏式织纹边框可以出现于顶部和局部底部；尽量避免每一个卡片都用厚重民族边框。
- 统一 Header、Footer、PageHero、SectionHeading、GiftCard、SceneSelector、PackageCard、ImagePlaceholder、ContactLink、ImageGallery 等组件与交互规范。
- 全站导航：首页 / 果礼定制 / 商务果切 / 团餐返图 / 关于我们，当前页高亮。主咨询以电话、微信联系为主，不是填写表单。微信未提供二维码前，显示“微信二维码待上传”的静态占位，不要使用无法扫码的二维码图样冒充可用。
- 移动端菜单、图片比例、字重、对比度、触控区域必须重新适配；不可直接缩小电脑稿。
- **藏文不可由模型想象拼写**；如果设计参考中藏文为生成伪字，请改用用户原始品牌图片的正确局部，或保留待提供的图片占位。

## 5. 果礼定制 `/gifts`

参考：`references/final/02-fruit-gifts.png`。

页面必须是用户做出选择的逻辑，而不是“几十张礼盒图片的长网页”：

**选系列 → 看系列商品 → 点详情 → 微信/电话咨询**。

可选系列 3 个：
- `french` 法式果礼：精致、优雅的混合精品水果礼盒，可有装饰包装。
- `tibetan` 藏式果礼：藏式包装与真实可供应的藏地特色水果组合。禁止把普通产品随便贴上西藏产地标签。
- `classic` 经典整箱果礼：传统纸箱/手提箱形式的**单品整箱水果**，例如猕猴桃、苹果、柑橘，不是带鲜花、丝带、摆件的豪华混合水果篮。实物形态见 `references/brand/classic-fruit-box-reference.png`。

系列选中后，内容区只展示本系列商品；从首页带来的 query 参数应正确初始化；用户返回时可用浏览器历史恢复导航状态。商品数量不足时显示“更多产品待上架”，不要编造“礼盒 A/B/C 的真实规格价格”。

产品详情提供：大图/图集、产品名称、组合水果、规格或重量（有数据才展示）、包装方式、使用场景、时令/供货说明（真实数据后启用）、电话/微信咨询。当前无具体商品资料时展示内容结构和示范占位，不把示意图当实物。

## 6. 商务果切 `/fruit-cuts`

参考：`references/final/03-fruit-cuts.png`。

严格单一路径：
1. 顶部选择**使用场景**，仅 5 个：
   - `beauty-spa` 美容院 / SPA
   - `hotel-vip` 酒店 / 贵宾接待
   - `wedding-birthday` 婚礼 / 生日宴
   - `brand-catering` 品牌活动 / 团餐
   - `office-meeting` 办公室 / 会议
2. 展示该场景特有的推荐套餐（先在数据中设置样例**占位套餐**，标识为“示意，待上架”，不伪装真实销售 SKU）。用户点击具体套餐查看详情。
3. **只在套餐详情页/详情弹层中**选择规格：小份 1 人、中份 2–3 人、大份 4–5 人；一次出现一个选择器，变更规格可更新对应照片、描述、份量（只在真实数据存在时）。
4. 最后微信/电话咨询，不填写预订表单，不制造假“下单成功”。

关键交互规则：
- 选择场景时只更新套餐列表；不自动把用户重定向到另一个无关套餐。
- 场景与套餐如果不兼容，清除不适用的套餐和规格选择，避免把前一个场景套餐错当当前场景套餐；若详情页已经在浏览，则提供明显的返回导航。
- 从首页 query 参数进入时选中正确场景。浏览器前进/后退保持正确状态。可以用 URL query/path 表达可分享状态。
- 本页**删除“其他场景推荐”**，不在规格区域重复场景卡片。页面视觉保持简洁。
- “美容养颜/补水/补 VC”等属于场景主题文案，不承诺疗效或具体身体改善；儿童/医疗有关用语保持谨慎。

## 8. 关于我们 `/about`

参考：`references/final/05-about-us.png`。

采用温暖、质朴、与高原风土有关的品牌语言。结构：品牌故事/文化缘起 → 选果与包装理念 → 品牌服务 → 门店/联系信息。未知门店照片、资质和真实产地证明一律占位/省略；不要虚构创业年份、团队规模、长期合作客户、产地保证或营业数据。

## 9. 图片与内容管理

`public/images/` 已按品牌、首页、果礼、果切、案例、关于、二维码建立空目录（带 `.gitkeep`）。**不要把 `references/final` 设计稿当作产品素材**。

开发结构化数据：
- `site`：品牌名/电话/门店地址可空/营业时间可空/微信二维码可空/藏文 logo 图片可空。
- `giftSeries`：id、名称、简短介绍、封面路径可空。
- `giftProducts`：id、系列、名称、可选描述、图片列表、规格、原料、包装、状态。默认占位，不得假装在售。
- `fruitCutScenes`：id、名称、介绍、图片可空。
- `fruitCutPackages`：id、所属 sceneId、名称、图片、简介、规格映射、状态。
- `cases`：id、所属 sceneId、标题/图片/可选日期/可选人数/描述，默认空列表。

图片缺失组件：统一占位、正确比例、提示“产品图片待上传 / 案例图片待上传 / 微信二维码待上传”。无真实营业信息则隐藏数值，不要出现诸如“8:30–20:30”这样未经确认的时间。

## 10. 设计/交互的验收标准

- 5 页可访问，导航、电话、微信占位提示、卡片跳转全部正常。
- 视觉统一，蓝/米白为主，文化元素适量，手机端无横向滚动与拥挤字体。
- 首页有**三类果礼入口 + 五类果切场景入口 + 案例预览**，不出现小中大规格。
- 果礼页面选定系列后**只展示该系列**。
- 果切只保留五个场景，用户**选场景 → 选套餐 → 在详情里选规格**，不会反复选择/意外丢失正确状态；不出现“其他场景推荐”。
- 经典整箱商品呈现原箱包装，与法式/藏式混合礼盒有明显区别。
- 所有页面无提交需求表单，无虚构经营事实，无假二维码/假案例。
- 页脚苹果果园主题已实现为**可替换素材槽位**，而不是旧抽象山峦占满底部。
- TypeScript、lint、production build 均通过；若具备浏览器工具，对桌面/手机视口拍截图并对照设计稿调整。
- 最后输出：启动方法、目录结构、五页 URL、图片/产品数据替换方法、实际验证记录、待用户提供资料清单。
